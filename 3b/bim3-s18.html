Documentação, testes unitários e depuração

Nesta semana você irá criar "asserts" simples e interpretar falhas para começar a praticar testes unitários e garantir que seu código funcione como esperado, mesmo após alterações.

Semana 18 • Aula 01

Docstrings e comentários eficazes

Documentar o código adequadamente é essencial para explicitar o comportamento esperado de funções e módulos, facilitando a legibilidade e manutenção por outros desenvolvedores[cite: 2].

  • Docstrings: Documentações embutidas diretamente no código que descrevem os objetivos, parâmetros e retornos de subrotinas.
Semana 18 • Aula 02

Introdução a testes unitários

Os testes unitários consistem na validação automatizada de pequenos blocos de código (unidades) utilizando asserções (`asserts`) para garantir que o resultado obtido corresponda ao esperado[cite: 2].

[Entrada de Teste] → Executa Função → [Valida com Assert] → (Sucesso / Falha)
Semana 18 • Aula 03

Técnicas básicas de depuração

A depuração (debugging) engloba métodos sistemáticos para rastrear o fluxo de execução de um programa, inspecionar variáveis em tempo de execução e identificar a origem de bugs[cite: 2].

Técnica de Depuração Aplicação Prática
Rastreio por Impressão Uso de saídas estratégicas no console para monitorar estados de variáveis.
Análise de Falhas Interpretação de mensagens de erro e rastreios de pilha (stack traces).
Semana 18 • Aula 04

Minikata TDD “Calculadora”

Nesta oficina prática, aplicamos o conceito de Desenvolvimento Orientado por Testes (TDD) escrevendo os testes antes de implementar a lógica funcional[cite: 2].

Atividade Prática • Kata de Testes Desenvolver testes unitários para as operações básicas de uma calculadora e, em seguida, programar as funções correspondentes até que todos os testes passem com sucesso.
